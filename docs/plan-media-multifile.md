# สื่อการสอน — การ์ดเดียวหลายไฟล์ (โหมดอ่านแบบ ebook)

สถานะ: **ทำแล้ว** 6 ก.ย. 2569 · เอกสารนี้เก็บ *เหตุผล* ของแต่ละทางเลือกไว้
สรุปสั้นสำหรับคนอ่านโค้ดอยู่ที่ `CLAUDE.md` หัวข้อ "สื่อการสอน"

## ปัญหาที่แก้

วันนี้ 1 การ์ด = 1 ไฟล์ และกดเปิด = `window.open` เด้งแท็บใหม่
ครูที่มีสื่อเป็นชุด (หนังสือ 14 บท, ใบงานสแกน 30 หน้า) ต้องสร้าง 30 การ์ด
หน้ารวมเละ และคนอ่านต้องเด้งแท็บทุกครั้งที่เปลี่ยนไฟล์

เป้าหมาย: **การ์ดใบเดียวถือหลายไฟล์ · เปิดอ่านในหน้าเดิม · สลับไฟล์จากสารบัญ**

---

## สิ่งที่ตัดสินใจแล้ว

### 1. ไฟล์อยู่ในตารางแยก ไม่ใช่ JSONB

ตารางใหม่ `media_files` ผูก `card_id` ไม่ใช่คอลัมน์ JSONB บน `media_cards`

เหตุผล: `purgeExpiredCards` กับ `getMediaStorageStatus` ยืนบน `file_key` / `sum(file_size)`
ที่เป็นคอลัมน์จริง — JSONB ต้องเขียน query ไล่ใหม่ทั้งชุด และการเพิ่ม/ลบไฟล์ทีละใบ
กลายเป็น read-modify-write ทั้ง array ซึ่งอัพหลายไฟล์พร้อมกันแล้วทับกันหาย

### 2. อ่านในหน้าเดิมด้วย iframe ไม่ใช่ pdf.js

modal เต็มจอ + `<iframe src=presignedURL>` ใช้ PDF viewer ของเบราว์เซอร์เอง

เหตุผลที่ไม่เอา pdf.js: **ต้องตั้ง CORS บน R2 bucket** เพราะ pdf.js `fetch` ข้าม origin
ส่วน iframe ไม่ต้อง · bucket สร้างใหม่ทุกโรงเรียน (`setup-new-school.md`)
= เพิ่มขั้นตอนติดตั้งที่ลืมแล้วพังเงียบ · แถมไม่ต้องโหลด lib ~1MB ทุกครั้งที่เข้าเมนู

**ราคาที่ยอมจ่าย**: สลับไฟล์ได้ แต่ **เลื่อนรวดข้ามไฟล์เหมือนเล่มเดียวไม่ได้** ·
iOS Safari เรนเดอร์ PDF ใน iframe ได้งั้น ๆ จึง **ต้องเก็บปุ่ม "เปิดในแท็บใหม่" ไว้ใน modal
เป็นทางหนี ห้ามลบทิ้ง** · viewer ของเบราว์เซอร์มีปุ่มดาวน์โหลด/พิมพ์ติดมาเอง กันไม่ได้
(ซึ่งเป็นจริงอยู่แล้ววันนี้ ไม่ได้แย่ลง)

### 3. ตั๋วเปิดไฟล์: ขอทีละใบ อายุ 1 ชม.

- **ขอตอนกดเปิดไฟล์นั้น (lazy)** ไม่ sign ล่วงหน้าทั้งการ์ด — การ์ด 30 ไฟล์จะได้ไม่ต้อง
  sign 30 URL ทิ้ง และไม่มีเคสตั๋วใบท้าย ๆ หมดอายุก่อนถูกใช้
- **ตั๋วผูกกับ `media_files.id` ไม่ใช่ `card_id`** — `disk.getFileUrl` เดิมเซ็น
  `{kind:'media', id: cardId}` แล้ว `routes/media.js` เอาไป `SELECT file_key FROM media_cards`
  ต้องเปลี่ยนเป็น join กลับหาการ์ดแม่เพื่อเช็ค `deleted_at` + `visible_levels`
- **ขยาย TTL เป็น 1 ชม. เฉพาะสื่อการสอน** (ส่ง ttl เป็น argument ของ `getFileUrl`
  ไม่แตะของสารบรรณที่ยัง 300 วิ)

> ⚠️ เหตุผลของ TTL — จุดที่ยังไม่มีใครเจอ
> PDF viewer ของเบราว์เซอร์โหลดไฟล์ใหญ่แบบ **Range request ทยอยขอตอนเลื่อน**
> ไม่ได้ดึงทีเดียวจบ · เปิดค้างอ่านเกิน 5 นาทีแล้วเลื่อนลงหน้าท้าย → range request
> ยิงด้วย URL ที่หมดอายุ → **PDF ค้างกลางเล่ม**
> วันนี้ไม่เจอเพราะเปิดแท็บใหม่แล้วอ่านจบเร็ว แต่โหมด ebook คนเปิดค้างนาน
> ราคา: URL หลุดออกไป = ใครถือก็เปิดได้ 1 ชม.

### 4. อัพทีละไฟล์ ยิงเรียงกัน ไม่ใช่ request เดียวหลายไฟล์

**เหตุผลหนัก**: multer ใช้ `memoryStorage()` — ไฟล์อยู่ใน RAM ทั้งก้อน
30 ไฟล์ × 25MB = 750MB เข้า memory ครั้งเดียว → **Railway ตาย**
แถมล้มใบเดียวไม่ล้มทั้งชุด retry เฉพาะใบที่พลาดได้ และทำ progress ต่อไฟล์ได้ตรง ๆ

ลำดับ:
```
1. saveMediaCard                      → ได้ card id (card_type='files')
2. POST /api/media/upload/:cardId ×N  → ทีละไฟล์ เรียงกัน
```
ต่างจากเดิมที่ `createPdfCard` สร้างการ์ด+ไฟล์ใน request เดียว
ราคา: ครูปิดหน้ากลางคัน = ได้การ์ดเปล่า — รับได้ ดีกว่าทำ staging area ที่ต้องมีตัวกวาดของตัวเอง

### 5. rate limit เปลี่ยนจากนับครั้งเป็นนับ MB

`RATE_LIMIT = { max: 20, windowSec: 3600 }` เดิมนับ **จำนวนครั้ง**
ครูอัพหนังสือ 30 บท = ชนเพดานตั้งแต่ใบที่ 21 → **ฟีเจอร์นี้พังทันทีที่ปล่อยถ้าไม่แก้**

เปลี่ยนเป็น **500MB/ชม./คน** — ตรงกับเจตนาเดิมที่คอมเมนต์เขียนไว้ว่า
"พื้นที่เก็บใช้ร่วมกันทั้งโรงเรียน คนเดียวยิงรัวจนเต็มได้ถ้าไม่กั้น"
คือกันพื้นที่ ไม่ใช่กันจำนวนครั้ง

เพิ่ม **เพดาน 50 ไฟล์/การ์ด** — กันการ์ดเดียวโตจนสารบัญใช้ไม่ได้

### 6. รับ PDF + JPG + PNG · ไม่รับ docx

`lib/storage/types.js` มีครบแล้ว ตรวจด้วย magic bytes อยู่แล้ว แค่เปลี่ยน `allowed`

- รูปคือเคสจริง — ครูสแกน/ถ่ายใบงานทีละหน้า ตรงกับ "เลื่อนดูทีละไฟล์" พอดี
- viewer แยกทางแค่ if เดียว: pdf → `<iframe>` · รูป → `<img>`
- **docx ไม่เอา** เพราะ `disposition: 'attachment'` บังคับดาวน์โหลด เปิดใน modal ไม่ได้เลย
  ใส่ไปก็เป็นหลุมในสารบัญ — ปล่อยให้เป็นของงานสารบรรณต่อไป

**ย่อรูปฝั่ง client ก่อนอัพ** ด้วย canvas จำกัดด้านยาว 2000px
(ภาพมือถือ 4032×3024 = 4-6MB/ใบ · 30 หน้า = 150MB ต่อการ์ดเดียว โควตาหมดเร็วกว่าที่คิด)
ทำใน browser ไม่ต้องลง `sharp` ที่ Railway — เป็น native binary เพิ่มเวลา build + ขนาด image

> ⚠️ กับดักของตัวย่อ: **PNG ต้อง export กลับเป็น PNG · JPG export เป็น JPEG**
> ถ้า `toBlob('image/jpeg')` เสมอ PNG พื้นโปร่งใสจะกลายเป็น **พื้นดำ**
> (canvas ว่าง = โปร่งใส → jpeg ไม่มี alpha) แผนภาพ PNG พื้นใสจะพังทั้งใบ
> **ไฟล์เล็กกว่า 1MB อยู่แล้วไม่ต้องย่อ** — เสี่ยงคุณภาพตกฟรี ๆ

### 7. `card_type` เปลี่ยน `'pdf'` → `'files'` · การ์ดผสมไม่ได้

รับรูปแล้วชื่อ `'pdf'` โกหก · เปลี่ยนตอนนี้ถูกกว่าอยู่กับชื่อผิดไปอีก 2 ปี
(มี precedent แล้ว: `drive_file_id` → `file_key` ตอนย้ายออกจาก Drive)

**การ์ดใบเดียวมีทั้งลิงก์และไฟล์ไม่ได้** เพราะ:
- ปุ่มแชร์ Google Classroom ใช้ได้เฉพาะการ์ดลิงก์ (ลิงก์แบบมีตั๋วแชร์ไปเปิดไม่ได้)
  ผสมแล้วต้องตอบว่า "แชร์อะไร"
- ปุ่มหลักบนการ์ดต้องมีคำตอบเดียวว่ากดแล้วไปไหน
- `_normalize` / `_normalizeMeta` แยกกันอยู่แล้วเพราะเรื่องนี้

อยากได้ทั้งคู่ = ทำ 2 การ์ด

### 8. ลบไฟล์เดี่ยว = ลบจริงทันที ไม่มีถังขยะระดับไฟล์

`lib/storage/index.js` เขียนไว้ตรง ๆ ว่า "ถังขยะ 30 วันอยู่ที่ DB ไม่ใช่ที่ storage ·
`deleted_at` เป็นแหล่งความจริงเพียงที่เดียว" และ `deleteMediaCard` เล่าว่าเคยมีสถานะ
2 ที่แล้วพัง — เพิ่ม `media_files.deleted_at` = ย้อนกลับไปที่เดิม
แถม "กู้คืนการ์ด" ต้องตอบว่ากู้ไฟล์ที่ลบแยกด้วยไหม ซึ่งไม่มีคำตอบสวย

**ราคา**: ลบผิด = หายเลย · ยอมรับได้เพราะครูมีไฟล์ต้นฉบับในเครื่อง อัพใหม่ 10 วินาที
ต่างจากการ์ดที่มีคำอธิบาย/สิทธิ์/กลุ่มสาระที่พิมพ์มาแล้ว · **ต้องมี confirm ก่อนลบ**

### 9. เรียงด้วยปุ่ม ↑↓ · ชื่อในสารบัญแก้ได้

- **ไม่เอา drag-drop** — บนมือถือห่วยและต้องลง lib เพิ่ม
- default เรียงตามลำดับที่อัพ ซึ่งตรงกับที่ครูเลือกไฟล์มาอยู่แล้ว
- **คอลัมน์ `label`** default = ชื่อไฟล์เดิม ครูกดแก้ทีหลังได้
  (สารบัญที่ขึ้นว่า `IMG_20260901.jpg` / `scan_001.pdf` ใช้ไม่ได้)
  ไม่บังคับตั้งชื่อตอนอัพ — จะทำให้อัพ 30 ไฟล์รวดไม่ได้

### 10. สิทธิ์คุมที่การ์ด ไม่มีสิทธิ์รายไฟล์

`visible_levels` คุมทั้งการ์ด ทุกไฟล์ในการ์ดใช้สิทธิ์เดียวกัน
ไม่ทำสิทธิ์รายไฟล์เพราะจะเกิดเคส "การ์ดเห็น แต่ไฟล์ที่ 7 ไม่เห็น" ที่ครูตั้งผิดแล้วไม่รู้ตัว
อยากแยก = แยกการ์ด (เฉลยไว้การ์ด "ครูเท่านั้น" ใบหนึ่ง)

### 11. เพดานพื้นที่รวมของโรงเรียน — ของใหม่

วันนี้ **ไม่มี guard เลย** `getMediaStorageStatus` แค่รายงาน ไม่ได้กั้น
เดิมไม่เป็นไรเพราะ rate limit 20 ครั้ง/ชม. กั้นทางอ้อม แต่ข้อ 5 เปลี่ยนเป็นนับ MB
และเปิดอัพรัว = ด่านนั้นหายไป

**เช็ค `sum(file_size)` ก่อนรับไฟล์ทุกใบ · เกินโควตา → 507** พร้อมข้อความบอกครู
ให้ไปลบของเก่า · โควตาจาก env `MEDIA_QUOTA_GB` (default 15) เพราะแต่ละโรงเรียน
bucket คนละขนาด
ถ้าไม่ทำ: โรงเรียนอัพจนเต็ม R2 แล้วรู้ตัวตอนบิลมา หรือตอนอัพพังแบบไม่มีข้อความอธิบาย

## schema

```sql
CREATE TABLE media_files (
  id         SERIAL PRIMARY KEY,
  card_id    INTEGER NOT NULL REFERENCES media_cards(id) ON DELETE CASCADE,
  file_key   TEXT NOT NULL,
  file_name  TEXT NOT NULL,          -- ชื่อไฟล์เดิมที่ครูอัพมา
  label      TEXT NOT NULL DEFAULT '',  -- ชื่อในสารบัญ ว่าง = ใช้ file_name
  file_size  BIGINT NOT NULL,
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_media_files_card ON media_files (card_id, sort_order, id);
CREATE INDEX idx_media_files_key  ON media_files (file_key);  -- ไล่หาไฟล์กำพร้า
```

> `ON DELETE CASCADE` เป็น **ตาข่ายกันแถวกำพร้า ไม่ใช่ตัวลบไฟล์**
> ต้องลบ object บน R2 ก่อนเสมอ ไม่งั้น cascade กินแถวไปแล้วไฟล์ค้างตลอดกาล ไม่มีอะไรชี้ถึง

### migration — ไฟล์เดียวจบ

ยืนยันแล้วว่า **production ยังไม่มีการ์ด PDF จริง** จึงไม่ต้องแยก 2 รอบ deploy

```
CREATE TABLE media_files ...
INSERT INTO media_files (card_id, file_key, file_name, label, file_size)
  SELECT id, file_key, file_name, COALESCE(file_name,''), file_size
  FROM media_cards WHERE file_key IS NOT NULL           -- no-op บน prod ปัจจุบัน
UPDATE media_cards SET card_type='files' WHERE card_type='pdf'
ALTER TABLE media_cards DROP CONSTRAINT <check เดิม>,
  ADD CHECK (card_type IN ('link','files'))
DROP INDEX idx_media_cards_file_key
ALTER TABLE media_cards DROP COLUMN file_key, DROP COLUMN file_name, DROP COLUMN file_size
```

drop คอลัมน์เก่าเลย ไม่ทิ้งไว้ — เหลือ 2 ที่ = โค้ดต้องมีสาขา `if` ว่าอ่านจากไหน
ซึ่งเป็นบั๊กที่เงียบที่สุด

## API

```
getMediaCardFiles(cardId)             ใหม่ — สารบัญของการ์ดใบเดียว
getMediaFileTicket(fileId)            แก้ argument: cardId → fileId
deleteMediaFile(fileId)               ใหม่ — ลบจริง ไม่เข้าถังขยะ
renameMediaFile(fileId, label)        ใหม่
reorderMediaFiles(cardId, [fileIds])  ใหม่
POST /api/media/upload/:cardId        แก้ — ผูกไฟล์เข้าการ์ดที่มีอยู่ (เลิกใช้ createPdfCard)
```

ทุกตัวเช็คสิทธิ์ผ่าน `_loadOwned(cardId)` เดิม — ครูแตะได้เฉพาะการ์ดตัวเอง Admin ได้หมด

**`getMediaCards` (หน้ารวม) ส่งแค่ตัวเลขสรุป**: `fileCount`, `totalSize` จาก aggregate
ไม่ส่งสารบัญมาด้วย — โรงเรียนมี 50 การ์ด × 30 ไฟล์ = 1,500 แถวยัดมาทุกครั้งที่เข้าเมนู
เสีย 1 round-trip ตอนเปิด modal (เร็วกว่าโหลด PDF อยู่แล้ว) แลกกับหน้ารวมไม่บวม

`meta` ยังเป็นป้ายที่ครูพิมพ์เอง **ไม่เติมอัตโนมัติ** — เขียนจำนวนไฟล์ลงคอลัมน์ที่ครูแก้ได้
จะเพี้ยนทันทีที่มีคนเพิ่ม/ลบไฟล์ · ชิป `"12 ไฟล์ · 34 MB"` คำนวณฝั่ง client
จาก `fileCount`/`totalSize` แทน (ต่างจากที่ร่างไว้ตอนแรก)

## UI

**การ์ดบนหน้ารวม**
- ปุ่ม `'เปิดไฟล์ PDF'` → **`'เปิดอ่าน'`** + chip `'12 ไฟล์'`
- **การ์ด `files` ที่มี 0 ไฟล์: นักเรียนไม่เห็น · ครู/Admin เห็นพร้อมป้าย "ยังไม่มีไฟล์"**
  ครูจะได้รู้ว่าค้างแล้วมาอัพต่อ ส่วนนักเรียนไม่ต้องเจอการ์ดกดแล้วว่างเปล่า
  **กรองที่ SQL** ตามกติกาเดิมของไฟล์นี้ ("ห้ามส่งออกไปแล้วซ่อนฝั่ง client")

**ตัวอ่าน** — `modal-fullscreen`
- ซ้าย: สารบัญ (label · ชนิด · ขนาด) · มือถือยุบเป็น offcanvas ที่กดปุ่ม "สารบัญ"
  (sidebar ตายตัวบนจอ 390px กินที่ครึ่งหน้า)
- ขวา: `<iframe>` สำหรับ PDF · `<img>` สำหรับรูป
- ล่าง: **← ก่อนหน้า / ถัดไป →** + คีย์ลูกศร (ครูสอนหน้าห้องกดรีโมทได้)
- ปุ่ม **"เปิดในแท็บใหม่"** — ทางหนีตอน iOS เรนเดอร์ไม่ไหว
- **จำไฟล์ล่าสุด** `localStorage['mediaLastFile_<cardId>']` เปิดครั้งหน้าเด้งไฟล์เดิม
  **ไม่จำเลขหน้าใน PDF** — iframe อ่านตำแหน่ง scroll ข้าม origin ไม่ได้

## ที่พังตอน deploy จริง (7 ก.ย. 2569)

deploy แรกเข้า `production` **ล้มที่ healthcheck** — `runMigrations()` เป็นขั้นเดียวใน
`server.js` ที่ล้มแล้วบล็อกไม่ให้ `app.listen()` (โดยตั้งใจ) แอปจึงไม่ขึ้นใน 30 วิ

```
migration 2026-09-06-media-multifile.sql ล้มเหลว:
new row for relation "media_cards" violates check constraint "media_cards_card_type_check"
```

**สาเหตุ**: เรียง `UPDATE card_type='files'` ไว้**ก่อน**บรรทัดที่ถอด CHECK เดิม
ตอน UPDATE ทำงาน constraint เก่ายังบังคับ `IN ('link','pdf')` อยู่

**ทำไมไม่มีเทสต์ไหนจับได้**: เทสต์ทุกตัวรันบน `media_cards` ที่ว่าง — dev ก็ว่างเพราะ
seed ล้างตารางก่อน · `UPDATE` แมตช์ 0 แถวจึงไม่มีอะไรไปละเมิด constraint
**DB เปล่ากับ DB ที่มีข้อมูลแบบเดิมเป็นคนละเส้นทาง** และเราเทสต์แค่เส้นทางแรก

**กันไม่ให้เกิดซ้ำ**: `test/migrate.test.js` เพิ่มเคสที่สร้างตารางแบบก่อน multifile
ใส่การ์ด `card_type='pdf'` จริง แล้วรันไฟล์ migration ทับ · ยืนยันแล้วว่าเทสต์นี้
**ล้มกับโค้ดเวอร์ชันที่พัง** ไม่ใช่เทสต์ที่ผ่านเปล่า ๆ

**ไม่มีข้อมูลเสียหาย** — `db/migrate.js` ห่อทั้งไฟล์ไว้ใน transaction เดียว ROLLBACK ครบ
และ Railway ไม่สลับไป deployment ที่ล้ม โรงเรียนยังรันตัวเก่าตลอด

## Q2 ถูกกลับคำหลังปล่อยจริง (7 ก.ย. 2569)

ตอนซักเลือก **A (iframe)** เหนือ **B (pdf.js)** ด้วยเหตุผลว่า pdf.js ต้องตั้ง CORS
ต่อ bucket ของทุกโรงเรียน = ขั้นตอนติดตั้งที่ลืมแล้วพังเงียบ · และรับความเสี่ยงข้อ
"iOS Safari เรนเดอร์ PDF ใน iframe ได้งั้น ๆ" ไว้ โดยมีปุ่มเปิดแท็บใหม่เป็นทางหนี

**ความเสี่ยงนั้นแรงกว่าที่ประเมิน**: บน iPad มันไม่ใช่ "งั้น ๆ" แต่คือ
**เห็นหน้าแรกหน้าเดียวและเลื่อนไม่ได้เลย** = ตัวอ่านใช้ไม่ได้บนเครื่องที่ครูใช้สอนจริง
ซึ่งทำให้เหตุผลทั้งหมดของฟีเจอร์นี้หายไปครึ่งหนึ่ง

ตอนนี้เป็น **pdf.js เป็นทางหลัก + iframe เป็น fallback อัตโนมัติ**
ข้อกังวลเดิมเรื่อง "ลืมตั้ง CORS แล้วพังเงียบ" แก้ด้วยการทำให้**ไม่เงียบ**:
ตั้งไม่ครบ = ตกไป iframe พร้อมแถบเหลืองบอกเหตุผลและปุ่มเปิดแท็บใหม่ ไม่ใช่จอว่าง
โรงเรียนเดิมจึงใช้ได้ต่อระหว่างทยอยตั้งค่า

**บทเรียน**: ตอนชั่งน้ำหนัก "ข้อจำกัดบนอุปกรณ์ที่ผู้ใช้จริงใช้" กับ "ขั้นตอนติดตั้ง
ที่เราควบคุมเองได้" — อย่างหลังแก้ได้ด้วยเอกสารกับ fallback ส่วนอย่างแรกแก้ไม่ได้เลย
