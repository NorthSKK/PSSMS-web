# แพ็กเกจครูคนเดียว — ผลการตัดสินใจ (2026-08-31)

สถานะ: **เลื่อนไว้ก่อน** ยังไม่ทำ จบงานขายโรงเรียนก่อน

## ข้อสรุปที่ตัดสินไปแล้ว ไม่ต้องเถียงใหม่

1. **จุดประสงค์ = funnel ไม่ใช่รายได้** ครูเดี่ยวคุ้มก็ต่อเมื่อพาไปสู่ดีลโรงเรียน
   ดีลโรงเรียนหนึ่งดีล (6,000–18,000฿/ปี) = ครูเดี่ยว 10–30 คน แต่ซัพพอร์ตหนักกว่ามาก
2. **ราคาเป้าหมาย 300฿/เทอม** (= 600฿/ปี/คน) ไม่ใช่ 2,500–3,000
3. **instance แยกต่อครูหนึ่งคน = ตาย** hosting ~2,200฿/ปี แพงกว่ารายได้ 3.7 เท่า
4. ราคานี้ต้องไม่ต่ำจนโรงเรียนเล็กให้ครูคนเดียวซื้อแทนแล้วแชร์กัน — ต้องผูกกับ quota

## ทางเทคนิคที่หาไว้แล้ว: 1 ครู = 1 Postgres schema

โค้ดนี้ทุก query ผ่าน `lib/db.js` ตัวเดียว (305 call sites, 35 ไฟล์, pool เดียว)
จึงสลับ `search_path` ต่อ request ได้ โดยไม่ต้องเติม `owner_id` ทีละจุด

ทำไมดีกว่าการเติม `owner_id`:
- Postgres บังคับ isolation เอง ไม่ต้องพึ่งความจำว่าเขียน `WHERE owner_id` ครบทุกที่
- ลืมจุดเดียวในแบบ `owner_id` = ข้อมูลนักเรียนจริงของครูคนอื่นรั่ว
- `db/schema.sql` ใช้ตัวเดิมทั้งดุ้น ไม่ต้องแก้

งานที่ต้องทำถ้ากลับมาทำ:
- `lib/db.js` — tenant context ที่ **fail closed**: ไม่มี context = `query()` ต้อง throw
  ห้ามปล่อยให้วิ่งบน schema default เด็ดขาด (pool ใช้ connection ซ้ำ search_path ค้างได้)
- `db/migrate.js` — วนรัน migration ทุก schema ตอน boot
- หน้าสมัครเอง + PromptPay (Stripe กิน 7% ของ 300฿ แพงเกิน)
- quota จำนวนนักเรียน + พื้นที่ไฟล์

เพดาน: ~100–200 ครู (26 ตาราง × N = 2,600–5,200 ตาราง) เกินนั้น catalog เริ่มอืด

## ข้อที่ยังไม่มีคำตอบ — และเป็นข้อที่ฆ่าโครงการนี้

ที่ 600฿/ปี/คน คุณมีเวลาให้ครูหนึ่งคนได้ **~2 ชั่วโมงตลอดปี** รวม onboarding
รวมตอบเมล รวมแก้บั๊กให้เขา

hosting คุ้มตั้งแต่ครู 11 คน — ปัญหาไม่ใช่เงิน ปัญหาคือครู 50 คนที่ LINE มาถาม
คนละ 3 ครั้ง/ปี = 150 ครั้ง ถ้าแก้ข้อนี้ไม่ได้ ทำ schema-per-teacher เสร็จก็ยัง
เหนื่อยกว่าเดิมและได้เงินน้อยกว่าเดิม

**อย่าเริ่มเขียนโค้ดจนกว่าจะตอบได้ว่าซัพพอร์ตจะเป็นศูนย์ได้ยังไง**
