สถานะ: **แผน ยังไม่เริ่มเขียนโค้ด**
เขียนเมื่อ 31 ส.ค. 2569 · ที่มา: การกริลล์เรื่องเว็บขาย ข้อ 7

## ประตูตัดสินใจ — อ่านก่อนเริ่ม

**ห้ามเริ่มเขียนจนกว่าจะมีหลักฐานว่ามีคนอยากใช้**

`pssms.app` เปิดรับ waitlist แล้ว เกณฑ์ที่ตั้งไว้:

| ผลใน 2-4 สัปดาห์ | ทำอะไรต่อ |
|---|---|
| **≥ 50 อีเมล** | เริ่มตามแผนนี้ |
| 15-49 | คุยกับ 5 คนก่อนว่าจะจ่ายจริงไหม แล้วค่อยตัดสิน |
| < 15 | ไม่ต้องทำ · ทุ่มไปที่ขายระดับโรงเรียนแทน |

เหตุผล: แผนนี้กินเวลาหลายสัปดาห์ และสร้าง multi-tenant ซึ่งเป็นความเสี่ยงที่
โครงปัจจุบันตั้งใจเลี่ยง — ไม่ควรจ่ายราคานั้นให้ลูกค้าที่ยังไม่รู้ว่ามีจริง

## อุปสรรคที่ใหญ่ที่สุด และไม่ใช่เรื่องเทคนิค

**ครูต้องมีรายชื่อนักเรียนก่อนถึงจะใช้อะไรได้เลย**

ในระบบของโรงเรียน รายชื่อถูก import มาแล้วโดยธุรการ ครูแค่เข้าไปใช้
ครูคนเดียวไม่มีใครทำให้ — ต้องพิมพ์ชื่อนักเรียน 40 คน × 4 ห้อง ด้วยตัวเอง
ก่อนจะได้ประโยชน์อะไรสักอย่าง

**นี่คือสิ่งที่จะฆ่าการใช้งานจริง ไม่ใช่ฟีเจอร์ที่ขาด** ต้องแก้ตั้งแต่วันแรก:

- **วางจาก Excel ได้** — ครูทุกคนมีไฟล์รายชื่ออยู่แล้ว textarea รับ paste
  แล้ว parse เลขที่/รหัส/ชื่อ เป็นทางหลัก ไม่ใช่ทางเลือก
- **อัปโหลด CSV** เป็นทางรอง
- **เริ่มด้วยเลขที่อย่างเดียวก็ได้** — ครูที่ยังไม่มีไฟล์กรอก "1-42" แล้วเช็คชื่อได้เลย
  ค่อยเติมชื่อทีหลัง · ได้ใช้งานภายใน 60 วินาทีแรก

วัดผลข้อนี้: **กี่ % ของคนสมัคร ที่เช็คชื่อสำเร็จอย่างน้อย 1 คาบ** ถ้าต่ำกว่า 40%
ปัญหาอยู่ที่ขั้นตอนนี้ ไม่ใช่ที่ฟีเจอร์

## ขอบเขต

**มี** — เฉพาะของที่ครูคนเดียวใช้ได้โดยไม่ต้องมีข้อมูลระดับโรงเรียน

| ฟีเจอร์ | หมายเหตุ |
|---|---|
| เช็คเวลาเรียน | ใช้ทุกวัน สร้างนิสัย |
| บันทึกคะแนน + พิมพ์ ปพ.5 | จุดที่ระบบพิสูจน์ตัวเอง (ปลายภาค) |
| แฟ้มบันทึกหลังสอน | ใช้ทำแฟ้มประเมิน |
| สื่อการสอน | ลิงก์ + ไฟล์ ใช้ `lib/storage/` เดิม |
| ตารางสอนของฉัน | ตารางง่าย ๆ ของครูคนเดียว ไม่ใช่ตารางทั้งโรงเรียน |

**ไม่มี** — ต้องมีข้อมูลทั้งโรงเรียน: บุคลากร งบประมาณ สารบรรณ จัดสอนแทน
แจ้งลา ชุมนุม แดชบอร์ดผู้บริหาร รายงานระดับโรงเรียน

## เอาอะไรจากของเดิมมาใช้

**คนละ repo** (`pssms-teacher`) — ไม่ใช่โฟลเดอร์ใน repo นี้
เพราะ push `main` ที่นี่ = deploy production ของทุกโรงเรียน
การแก้แอปครูไม่ควร restart ระบบที่ครูโรงเรียนอื่นใช้อยู่

| ของ | ทำยังไง |
|---|---|
| `lib/db.js`, `db/migrate.js`, `lib/storage/*` | **คัดลอกมาทั้งก้อน** เสถียรแล้ว แก้น้อย |
| แนวการเทสต์ (`test/helpers/api.js`) | คัดลอกแนว ไม่ใช่ไฟล์ |
| **กฎ มส. / เวลาเรียน** (`functions/attendanceReport.js`) | คัดลอกสูตร + ใส่คอมเมนต์ชี้ว่าต้นฉบับอยู่ไหน |
| **กฎคะแนน ปพ.5** (`functions/scores.js`, `generatePP5Template.js`) | เหมือนกัน |
| shim `google.script.run` | **ไม่เอา** เป็นมรดกจาก GAS แอปใหม่เขียน REST ตรง ๆ |
| โครง `users` + role | **ไม่เอา** คนละโมเดล (บัญชีสมัครเอง ไม่ใช่ธุรการสร้างให้) |

⚠️ **ยอมรับว่ากฎจะแตกกันได้** ระหว่างสอง repo — แก้สูตร มส. ที่หนึ่งต้องไปแก้อีกที่
ทำ shared package ไม่คุ้มสำหรับคนเขียนคนเดียว แต่ต้องเขียนคอมเมนต์ให้ชัดว่ามีคู่แฝดอยู่

## Multi-tenant — จุดที่พลาดไม่ได้

ทุกตารางมี `owner_id` และกรองทุก query · **ป้องกัน 3 ชั้น** เพราะชั้นเดียวคือรอวันหลุด

**ชั้น 1 — schema**
`owner_id TEXT NOT NULL REFERENCES accounts(id)` ทุกตารางข้อมูล ไม่มีข้อยกเว้น

**ชั้น 2 — Postgres RLS เป็นตาข่ายรอง**

```sql
ALTER TABLE students ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant ON students
  USING (owner_id = current_setting('app.owner_id', true));
```

ทุก request ตั้ง `SET LOCAL app.owner_id` ใน transaction เดียวกัน
**ลืม `WHERE owner_id` แล้วยังไม่หลุด** — นี่คือสิ่งที่ทำให้กล้าทำ multi-tenant
ทั้งที่เคยตัดสินใจเลี่ยง

**ชั้น 3 — ทางเข้า DB ทางเดียว**
ห้ามเรียก `query()` ตรงจาก handler · ผ่าน repository ที่บังคับรับ `ownerId` เป็น argument
ลืมส่ง = TypeError ตอนพัฒนา ไม่ใช่ข้อมูลหลุดตอน production

**เทสต์ที่ต้องมีตั้งแต่วันแรก** — ทุกตาราง ทุก endpoint: ครู A อ่าน/แก้/ลบของครู B ไม่ได้
เขียนเป็น loop วนทุก endpoint ไม่ใช่เขียนทีละอัน

## Auth

**ห้ามลอกของเดิม** — `checkLogin.js` เทียบรหัสผ่านเป็น plaintext ใน SQL
และ `pssms_creds` เก็บ `user:pass` base64 ใน localStorage
ยอมรับได้ในระบบปิดของโรงเรียนเดียว **ยอมรับไม่ได้กับบัญชีสาธารณะ**

- รหัสผ่าน hash ด้วย **argon2id** (หรือ bcrypt)
- ยืนยันอีเมลก่อนใช้งาน · ลืมรหัสผ่านผ่านลิงก์หมดอายุ
- session เป็น **refresh token ใน httpOnly cookie** + access token อายุสั้น
  ไม่เก็บรหัสผ่านไว้ในเบราว์เซอร์เด็ดขาด
- ส่งอีเมลด้วย Resend หรือ SES (ถูกมากที่ปริมาณนี้)
- rate limit หน้า login และ reset

## ที่เก็บไฟล์

ใช้ `lib/storage/` เดิมได้เลย · driver `s3` ชี้ R2

ต่างจากของโรงเรียน: **bucket เดียวสำหรับครูทุกคน** แยกด้วย prefix `<owner_id>/`
(bucket ต่อคนไม่ไหวเมื่อมีครูหลักพัน) — key ยังสุ่มเหมือนเดิม และตรวจสิทธิ์ตอนออก
presigned URL เหมือนเดิม

โควตา: ฟรี 50MB · จ่ายแล้ว 2GB — กันคนใช้เป็นที่ฝากไฟล์

---

## ฟรี vs จ่าย

**ฟรีถาวรแบบจำกัด ไม่มีเส้นตาย** (ตัดสินไว้แล้วในการกริลล์ ข้อ 9)

| | ฟรี | จ่าย |
|---|---|---|
| วิชา × ห้อง | 1 | ไม่จำกัด |
| นักเรียน | 60 | ไม่จำกัด |
| สื่อการสอน | 10 การ์ด · 50MB | ไม่จำกัด · 2GB |
| พิมพ์ ปพ.5 | ได้ | ได้ |
| ดาวน์โหลดข้อมูลออก | **ได้** | ได้ |

**ให้พิมพ์ ปพ.5 และ export ได้ในแพ็กฟรี** — จับข้อมูลครูเป็นตัวประกันคือวิธีที่ดี
ที่สุดในการทำให้ครูเลิกใช้และไปบอกต่อในทางลบ · ตัวกระตุ้นให้จ่ายคือ "ผมสอน 4 วิชา"
ไม่ใช่ "ผมออกข้อมูลไม่ได้"

**บังคับ limit ที่ server เท่านั้น** ไม่ใช่ซ่อนปุ่มฝั่ง client

## เก็บเงิน

**รายปี ไม่ใช่รายเดือน** — PromptPay ตัดอัตโนมัติรายเดือนไม่ได้ และครูไทยจำนวนมาก
ไม่มีบัตรหรือไม่อยากผูกบัตร · รายปีจ่ายครั้งเดียวจบด้วย PromptPay

- **Stripe Checkout** (รองรับไทย รับทั้ง card และ PromptPay) — ไม่เขียนหน้าจ่ายเงินเอง
- ราคายังไม่ตัดสิน กรอบที่คุยไว้ ~590 บาท/ปี (ถูกกว่าหนังสือเรียนเล่มเดียว
  ครูอนุมัติตัวเองได้)
- คนใน waitlist ได้ราคาพิเศษตลอดอายุการใช้งาน ตามที่ประกาศบนเว็บแล้ว
- **ยังไม่ต้องทำระบบจ่ายเงินในเฟสแรก** — เปิดฟรีล้วนก่อน ใส่ paywall เมื่อมีคนใช้จริง
  ต่อเนื่อง · เก็บเงินจากระบบที่ยังไม่มีใครใช้คือแก้ปัญหาผิดข้อ

## โฮสต์และต้นทุน

instance เดียวรวมครูทุกคน — ต่างจากโรงเรียนที่แยก deployment

- Railway 1 service + 1 Postgres · R2 1 bucket
- ที่ครู 1,000 คน ประมาณไม่เกินหลักพันบาท/เดือน (ต้องวัดจริง)
- `<something>.pssms.app` เช่น `app.pssms.app` หรือ `teacher.pssms.app`

## ลำดับการทำ

**เฟส 0 — ตัดสินใจ** · ดูตัวเลข waitlist ตามเกณฑ์ด้านบน

**เฟส 1 — โครง + ฟีเจอร์เดียวให้จบวงจร (~1 สัปดาห์)**
สมัคร/ยืนยันอีเมล/ล็อกอิน · RLS + repository layer · migrate runner ·
**นำเข้ารายชื่อด้วยการ paste** · เช็คเวลาเรียน · เทสต์ isolation ครบทุก endpoint

จบเฟสนี้ต้อง **ปล่อยให้ครูจริงใช้ได้แล้ว** ไม่ใช่รอครบทุกฟีเจอร์
เช็คชื่อคือของที่ใช้ทุกวันและง่ายที่สุด — สร้างนิสัยก่อน

**เฟส 2 — ปพ.5 (~1-2 สัปดาห์)** กรอกคะแนน + สูตรรวม + พิมพ์
นี่คือจังหวะที่ครูรู้สึกว่าคุ้ม ต้องมาก่อนสิ้นภาคเรียนแรกที่มีคนใช้

**เฟส 3 — สื่อการสอน + บันทึกหลังสอน + ตารางสอน**

**เฟส 4 — limit ของแพ็กฟรี + Stripe** ทำเมื่อมีคนใช้ต่อเนื่องแล้วเท่านั้น

## ทางขึ้นจากครู → โรงเรียน

ครูที่ใช้แล้วชอบคือคนที่จะไปบอก ผอ. — **ช่องทางขายที่ถูกที่สุดที่มี**

ออกแบบให้รองรับตั้งแต่แรก โดยไม่ต้องสร้างอะไรเพิ่มตอนนี้:
- export ของครูเป็นรูปแบบที่ import เข้าระบบโรงเรียนได้ (คะแนน เช็คชื่อ รายชื่อ)
- อย่าใช้ id ที่ผูกกับ instance เดียวจนย้ายไม่ได้

**ยังไม่ต้องเขียนตัว import** — แค่อย่าปิดประตูตัวเอง

## ความเสี่ยง

| เสี่ยง | ถ้าเกิดจะรู้ได้ยังไง | กัน |
|---|---|---|
| **ครูไม่ยอมกรอกรายชื่อ** (เสี่ยงสุด) | % คนที่เช็คชื่อสำเร็จ < 40% | paste จาก Excel · เริ่มด้วยเลขที่ได้ |
| ข้อมูลครูคนหนึ่งไปโผล่ที่อีกคน | เทสต์ isolation ตก | 3 ชั้น + RLS + เทสต์ทุก endpoint |
| กฎ ปพ.5 สองที่แตกกัน | ผลไม่ตรงกับระบบโรงเรียน | คอมเมนต์ชี้ต้นฉบับ · เทสต์ด้วยเคสเดียวกัน |
| สมัครแล้วไม่กลับมา | active คาบที่ 2 < 30% | เฟส 1 ต้องใช้ได้จริงภายใน 2 นาทีแรก |
| ทำเสร็จแล้วไม่มีคนจ่าย | conversion < 3% | ไม่ทำ paywall จนกว่าจะมีคนใช้จริง |

## สิ่งที่แผนนี้จงใจไม่ทำ

- ไม่ทำ multi-tenant ในระบบของโรงเรียน — คนละโปรดักต์ คนละ repo คนละ DB
- ไม่ทำแอปมือถือ native — เว็บบนมือถือพอ
- ไม่ทำระบบจ่ายเงินก่อนมีคนใช้
- ไม่ทำ import จากระบบครู→โรงเรียน จนกว่าจะมีโรงเรียนที่ขอจริง
