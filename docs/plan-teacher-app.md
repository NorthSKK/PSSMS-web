## ขอบเขต

**มี** — เฉพาะของที่ครูคนเดียวใช้ได้โดยไม่ต้องมีข้อมูลระดับโรงเรียน:

**ไม่มี** — บุคลากร งบประมาณ สารบรรณ จัดสอนแทน แจ้งลา ชุมนุม แดชบอร์ดผู้บริหาร
รายงานระดับโรงเรียน · **ไม่มี role แอดมินโรงเรียน** ครูเป็นแอดมินของข้อมูลตัวเอง

## โครงเมนู

**ห้องเรียนเป็นศูนย์กลาง** — งานของครูผูกกับห้อง ไม่ใช่ผูกกับฟีเจอร์

```
แถบล่าง:  หน้าแรก · ห้องเรียน · สื่อ · เพิ่มเติม

หน้าแรก      คาบถัดไป + ตารางวันนี้ + ปุ่มลัด "เช็คชื่อคาบนี้"
ห้องเรียน     รายการห้อง → เข้าห้อง → แท็บ เช็คชื่อ / คะแนน / บันทึกหลังสอน / รายชื่อ
สื่อ          การ์ดสื่อการสอน
เพิ่มเติม     ตารางสอน · บัญชี · ปลดล็อก · ดาวน์โหลดข้อมูล
```

**ปุ่ม "+ เพิ่มห้อง" ในรายการห้องคือจุดขาย** — ครูฟรีเห็นห้องเดียว กดเพิ่มแล้วเจอหน้าปลดล็อก
ตัวกระตุ้นอยู่ในที่ที่ครูนึกถึงมันพอดี ไม่ต้องมีแบนเนอร์ที่ไหน

**หน้าเช็คชื่อคือหน้าที่ต้องดีที่สุด** — ครูยืนหน้าห้อง กดด้วยนิ้วโป้งมือเดียว ปุ่มใหญ่ เลื่อนน้อย

### เน็ตในห้องเรียน

ครูเช็คชื่อในห้องที่สัญญาณอ่อน กดแล้วหมุนค้าง = เลิกใช้

- กดแล้ว**เปลี่ยนหน้าจอทันที** ไม่รอ server
- คิวส่งใน `localStorage` ส่งเบื้องหลัง ล้มก็ลองใหม่
- แถบสถานะ "ยังไม่ได้บันทึก 3 รายการ" **ห้ามเงียบ**
- ⚠️ **ห้ามบอกว่าบันทึกแล้วทั้งที่ยังไม่ถึง server** — บทเรียนจาก `uploadSarabunFile`

## Multi-tenant — จุดที่พลาดไม่ได้

ทุกตารางมี `owner_id` · **ป้องกัน 3 ชั้น** เพราะชั้นเดียวคือรอวันหลุด

**ชั้น 1 — schema** · `owner_id TEXT NOT NULL REFERENCES accounts(id)` ทุกตารางข้อมูล ไม่มีข้อยกเว้น

**ชั้น 2 — Postgres RLS เป็นตาข่ายรอง**

```sql
ALTER TABLE students ENABLE ROW LEVEL SECURITY;
CREATE POLICY tenant ON students
  USING (owner_id = current_setting('app.owner_id', true));
```

ทุก request ตั้ง `SET LOCAL app.owner_id` ใน transaction เดียวกัน
**ลืม `WHERE owner_id` แล้วยังไม่หลุด** — นี่คือสิ่งที่ทำให้กล้าทำ multi-tenant

**ชั้น 3 — ทางเข้า DB ทางเดียว** · ห้ามเรียก `query()` ตรงจาก handler
ผ่าน repository ที่บังคับรับ `ownerId` เป็น argument — ลืมส่ง = TypeError ตอนพัฒนา

**เทสต์ตั้งแต่วันแรก**: loop ทุก endpoint ตรวจว่าครู A อ่าน/แก้/ลบของครู B ไม่ได้
เขียนเป็น loop ไม่ใช่ทีละอัน — endpoint ใหม่จะถูกครอบอัตโนมัติ

## Auth

**ห้ามลอกของเดิม** — `checkLogin.js` เทียบรหัสผ่าน plaintext ใน SQL และเก็บ
`user:pass` base64 ใน localStorage · ยอมรับได้ในระบบปิดของโรงเรียน **ยอมรับไม่ได้กับบัญชีสาธารณะ**

**สองทางเข้า**: Google sign-in (scope `openid email profile` — non-sensitive ไม่ต้อง verify)
และอีเมล+รหัสผ่าน (argon2id)

**กติกาผูกบัญชี — `email_verified` เป็นตัวตัดสินเดียว**

| สถานการณ์ | ทำอะไร |
|---|---|
| Google · ยังไม่มีบัญชี | สร้างใหม่ `email_verified = true` |
| Google · มีบัญชีรหัสผ่านอยู่ | **ผูกเข้าบัญชีเดิม** (Google พิสูจน์ความเป็นเจ้าของแล้ว) |
| สมัครรหัสผ่าน · มีบัญชี Google อยู่ | **ห้ามสร้างใหม่ ห้ามตั้งรหัสผ่านทันที** → ส่งลิงก์ไปอีเมลก่อน |
| อีเมลยังไม่ยืนยัน | ใช้ได้แต่จำกัด · ห้ามให้ผูก Google เข้าบัญชีที่ยังไม่ยืนยัน |

⚠️ **ช่องที่ 3 คือช่องยึดบัญชี** — ถ้าปล่อยให้ตั้งรหัสผ่านทับบัญชีที่มีอยู่ ใครที่รู้อีเมลครู
ก็ยึดบัญชีไปพร้อมคะแนนนักเรียนทั้งหมด

**Schema**: `accounts` (id, email, email_verified) + `identities` (account_id, provider, provider_uid)
เพิ่มทางเข้าใหม่ทีหลังไม่ต้องรื้อ

**ต้องเตรียม**: หน้า privacy policy กลับมา (เคยเขียนแล้วลบไปตอนเลิกใช้ Drive) + homepage
ชี้ `pssms.app` — ทั้งคู่จำเป็นตอน publish OAuth consent screen
คราวนี้ผ่านได้เพราะมีโดเมนของตัวเองแล้ว ต่างจากตอนที่ติดเพราะ `*.up.railway.app`

## ฟรี vs จ่าย

| | ฟรี | ปลดล็อกเต็ม (~590฿ ครั้งเดียว) |
|---|---|---|
| วิชา × ห้อง | **1 คู่** | ไม่จำกัด |
| นักเรียน | 60 | ไม่จำกัด |
| สื่อการสอน | 10 การ์ด · 50MB | ไม่จำกัด · 2GB |
| **พิมพ์ ปพ.5** | **ได้** | ได้ |
| **ดาวน์โหลดข้อมูลออก** | **ได้** | ได้ |
| เก็บย้อนหลัง | 1 ปีการศึกษา | ไม่จำกัด |

**เหตุผลที่พิมพ์ ปพ.5 ต้องฟรี**: ครูกรอกคะแนนทั้งเทอมแล้วพิมพ์ไม่ได้ตอนปลายภาค
= หายนะของเขา เขาจะไม่จ่าย เขาจะด่าในกลุ่มไลน์ครูแล้วกลับไปใช้ Excel
โมเดลนี้ต้องขายที่ **"อยากทำได้มากกว่านี้"** ไม่ใช่ **"ติดอยู่"**

**บังคับ limit ที่ server เท่านั้น** ไม่ใช่ซ่อนปุ่มฝั่ง client

**ตาราง `entitlements`** — บัญชีนี้ปลดล็อกอะไร + เหตุผล (`purchase` / `founder` / `manual`)
ข้อเสนอ "100 คนแรกฟรีตลอดชีพ" ทำผ่าน `grant.js` ไม่ต้องมีเงื่อนไขในโค้ด

## รับเงิน

**PromptPay QR + ตรวจสลิปอัตโนมัติ** (SlipOK / EasySlip) — ไม่เสีย % ไม่ต้องจดบริษัท
เข้าบัญชีตรง · ต่างจาก Stripe ที่กิน ~32฿/รายการ และน่าจะต้องเป็นนิติบุคคล
(**เช็คเงื่อนไขปัจจุบันเองอีกที**)

**สร้าง QR เอง** — PromptPay เป็นสเปกเปิด (EMVCo) ประกอบ payload พร้อมยอด 590 ตายตัว
ในโค้ด ~40 บรรทัด ครูสแกนแล้วยอดขึ้นเอง กรอกผิดไม่ได้

**บริการตรวจสลิปบอกได้แค่ว่าสลิปจริง** ต้องตรวจเพิ่มเองทั้ง 4 ข้อ:

| ตรวจ | กันอะไร |
|---|---|
| **เลขอ้างอิงต้องไม่เคยใช้** (`UNIQUE`) | ส่งสลิปใบเดียวกันต่อในกลุ่มไลน์ ปลดล็อกกันทั้งกลุ่ม |
| **บัญชีปลายทางตรงกับของเรา** | เอาสลิปโอนค่าข้าวให้เพื่อนมาใช้ |
| **ยอด ≥ 590** | โอน 10 บาทแล้วปลดล็อก |
| **เวลาโอนภายใน 24 ชม.** | สลิปเมื่อ 3 เดือนก่อน |

- เก็บสลิปไว้ใน `lib/storage/` เผื่อสอบสวนและเป็นหลักฐาน
- **บริการตรวจล่ม → `pending` + แจ้ง "ตรวจสอบภายใน 24 ชม."**
  ห้ามปลดล็อกเพราะตรวจไม่ได้ และห้ามปฏิเสธเงียบ ๆ
- ตาราง `purchases` สถานะ `pending / paid / rejected` ตั้งแต่แรก
- ⚠️ **ครูจ่ายแล้วต้องไม่รอเกิน 24 ชม.** ถ้ารู้ว่าจะไม่ว่าง ปิดปุ่มซื้อดีกว่ารับเงินแล้วเงียบ

## เอาอะไรจากของเดิมมาใช้

**repo แยก `pssms-teacher`** — push `main` ที่นี่ = deploy production ของทุกโรงเรียน
แอปครูไม่ควรทำให้ระบบที่ครูโรงเรียนอื่นใช้อยู่ restart

| ของ | ทำยังไง |
|---|---|
| `lib/db.js` · `db/migrate.js` · `lib/storage/*` | **คัดลอกทั้งก้อน** เสถียรแล้ว |
| แนวเทสต์ (`test/helpers/api.js`) | คัดลอกแนว ไม่ใช่ไฟล์ |
| design token จาก `src/Styles.html` | ตัดเอาเฉพาะที่ใช้ |
| **กฎ มส./เวลาเรียน** (`functions/attendanceReport.js`) | คัดลอกสูตร + คอมเมนต์ชี้ต้นฉบับ |
| **กฎคะแนน ปพ.5** (`functions/scores.js`, `generatePP5Template.js`) | เหมือนกัน |
| shim `google.script.run` | **ไม่เอา** — มรดกจาก GAS เขียน REST ตรง |
| `users` + role | **ไม่เอา** — คนละโมเดล |

⚠️ **กฎ ปพ.5 กับ มส. จะแตกกันได้ระหว่างสอง repo** — แก้สูตรที่หนึ่งต้องไปแก้อีกที่
shared package ไม่คุ้มสำหรับคนเขียนคนเดียว แต่ต้องคอมเมนต์ให้ชัดว่ามีคู่แฝด
และเทสต์ด้วยเคสเดียวกันทั้งสองฝั่ง

## ลำดับการทำ

**เฟส 1 — ปล่อยให้ครูจริงใช้ (~2 สัปดาห์)**
auth ทั้งสองทาง + ผูกบัญชี · RLS + repository layer · migrate runner ·
**นำเข้ารายชื่อด้วยการ paste** · ห้องเรียน + เช็คชื่อ (มีคิว offline) ·
เพดาน + PromptPay + ตรวจสลิป · เทสต์ isolation ครบทุก endpoint

จบเฟสนี้ **ปล่อยจริงเลย** ไม่รอครบทุกฟีเจอร์ — เช็คชื่อคือของที่ใช้ทุกวันและง่ายที่สุด
สร้างนิสัยก่อน

**เฟส 2 — ปพ.5 (~1-2 สัปดาห์)** กรอกคะแนน + สูตรรวม + พิมพ์
ต้องเสร็จก่อนสิ้นภาคเรียนแรกที่มีคนใช้ เพราะนั่นคือจังหวะที่ครูรู้สึกว่าคุ้ม

**เฟส 3** สื่อการสอน · บันทึกหลังสอน · ตารางสอน

**เฟส 4** ลดงานมือ — ตรวจจับครูโรงเรียนเดียวกันแล้วเสนอแพ็กเกจโรงเรียน · หน้าแอดมิน (ถ้าจำเป็น)

## ทางขึ้นจากครู → โรงเรียน

ครูที่ใช้แล้วชอบคือคนที่จะไปบอก ผอ. — **ช่องทางขายที่ถูกที่สุดที่มี**

ออกแบบให้รองรับ โดยยังไม่ต้องสร้าง:
- export ของครูเป็นรูปแบบที่ import เข้าระบบโรงเรียนได้
- อย่าใช้ id ที่ผูกกับ instance เดียวจนย้ายไม่ได้
- นับครูที่กรอกชื่อโรงเรียนเดียวกัน = ลีดที่ร้อนที่สุด

## ความเสี่ยง

| เสี่ยง | รู้ได้ยังไง | กัน |
|---|---|---|
| **ครูไม่ยอมกรอกรายชื่อ** (สูงสุด) | % คนที่เช็คชื่อสำเร็จ < 40% | paste จาก Excel · เริ่มด้วยเลขที่ |
| ข้อมูลครูคนหนึ่งไปโผล่ที่อีกคน | เทสต์ isolation ตก | 3 ชั้น + RLS + loop ทุก endpoint |
| สลิปปลอม/สลิปซ้ำ | ยอดโอนไม่ตรงกับจำนวนที่ปลดล็อก | ตรวจครบ 4 ข้อ · `UNIQUE` เลขอ้างอิง |
| กฎ ปพ.5 สองที่แตกกัน | ผลไม่ตรงกับระบบโรงเรียน | คอมเมนต์ชี้ต้นฉบับ · เทสต์เคสเดียวกัน |
| สมัครแล้วไม่กลับมา | active คาบที่ 2 < 30% | ต้องใช้งานได้จริงใน 2 นาทีแรก |
| ไม่มีใครจ่าย | conversion < 3% หลังมีคนใช้ 100 | คุยกับ 100 คนแรกก่อนตัดราคาจริง |

## สิ่งที่จงใจไม่ทำ

- ไม่ยัด multi-tenant เข้าระบบโรงเรียน — คนละโปรดักต์ คนละ repo คนละ DB
- ไม่มีหน้าแอดมินของผู้ดูแล จนกว่า support จะเกิน ~5 เคส/สัปดาห์
- **ไม่มี impersonate ไม่ว่าเฟสไหน** — เปิดดูคะแนนนักเรียนของครูคนอื่นได้
  คือสิ่งที่ทำลายความไว้ใจทั้งหมด · ตอบ support จาก **สถานะ** ไม่ใช่เนื้อหา
- ไม่ให้ครูแชร์ห้องเรียนกัน — จะกลายเป็นระบบโรงเรียนย่อส่วนโดยไม่ตั้งใจ
- ไม่ทำแอปมือถือ native — เว็บบนมือถือพอ
- ไม่มีเหรียญ/กระเป๋าเงินในระบบ — ค่าธรรมเนียมกับภาระผูกพันไม่คุ้ม
- ไม่ทำ import ครู→โรงเรียน จนกว่าจะมีโรงเรียนที่ขอจริง
