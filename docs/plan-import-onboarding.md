# แผน — นำเข้าข้อมูลและตั้งค่าโรงเรียนใหม่

สถานะ: **เสร็จครบทั้ง 4 รอบ** (3 ก.ย. 2569) — โรงเรียนใหม่ตั้งค่า นำเข้าข้อมูล
และมีคู่มือทั้งฝั่งเราและฝั่งโรงเรียนแล้ว · ผ่านการกริลล์ 15 ข้อ
ADR ที่เกี่ยว: [`0003-import-people-upsert-timetable-replace`](./adr/0003-import-people-upsert-timetable-replace.md)

## ปัญหา

ระบบขายเป็นผลิตภัณฑ์แล้ว (1 โรงเรียน = 1 deployment) แต่ทางเข้าข้อมูลยังเป็นของ
โรงเรียนเดียว — โรงเรียนที่สองที่ซื้อไปจะเจอสามด่านนี้

### 1. ปุ่มนำเข้า 4 ใน 5 ตัวพังเงียบ ขึ้นว่า "สำเร็จ"

frontend อ่านไฟล์เป็น **base64 string** แล้วส่งไป ส่วน backend รอ **array ของแถว**
`Array.isArray(rows)` เป็น false ทุกครั้ง จึงคืนทางลัดบรรทัดแรกว่า
`{ status:'success', message:'นำเข้า 0 รายการ' }` — หน้าจอขึ้นเครื่องหมายถูก ไม่มีอะไรเข้า DB

| RPC | frontend ส่ง | backend รับ | สภาพ |
|---|---|---|---|
| `importStudentCSV` | base64 (`Scripts_Admin.html:671`) | `[rows, year]` | พังเงียบ |
| `importTeacherCSV` | base64 | `[rows]` | พังเงียบ |
| `importTimetableCSV` | base64 + `clearOld` | `[rows]` | พังเงียบ + `clearOld` ตกหาย |
| `importCalendarCSV` | base64 (`_calImportBase64`) | `[rows]` | พังเงียบ ทั้งที่หน้า preview ถูกต้อง |
| `importCurriculumCSV` | rows array | `[rows, clearOld]` | **ตัวเดียวที่ทำงาน** |

เป็นซากจากตอนย้ายจาก GAS — ของเดิม backend ฝั่ง GAS เป็นคน decode base64

### 2. ไม่มีแม่แบบให้กรอก

มีปุ่มดาวน์โหลดแม่แบบอยู่หน้าเดียวคือปฏิทิน (`Page_Calendar.html:127`)
หน้านักเรียน/ครู/ตารางสอนไม่มี — ธุรการต้องเดาหัวตารางจากศูนย์
และ `docs/templates/` ว่างเปล่า

### 3. ไม่มีเส้นทางตั้งค่าเริ่มต้น

โรงเรียนใหม่ login ด้วย `admin/1234` แล้วเจอหน้าเปล่า ไม่มีอะไรบอกว่าต้องทำอะไรต่อ
และ `getSystemConfig.js:11` hardcode `'โรงเรียนภูพระบาทวิทยา'` เป็นค่า default
(อีกจุดที่ `missing.js:502`) — **ผิดกฎ "อย่า hardcode ชื่อโรงเรียน" ใน CLAUDE.md**
โรงเรียนใหม่จะเห็นชื่อภูพระบาทบนหัวเว็บและบนเอกสาร ปพ.5 จนกว่าจะมีคนไปตั้ง
ปีการศึกษาก็ default ค้างไว้ที่ `2568`

## ทำไม spec ต้องเป็นไฟล์เดียว

`lib/importSpec.js` (ไม่แตะ DB) นิยามทุกคอลัมน์ครั้งเดียว: หัวไทย · alias · บังคับไหม ·
ตัวอย่าง · กติกาตรวจ แล้วมีคนใช้สามที่

```
lib/importSpec.js
   ├─ backend validate ตอนรับ rows เข้ามา
   ├─ getImportSpec (RPC) ──> frontend parse หัวตารางที่โรงเรียนส่งมา
   └────────────────────────> frontend สร้างไฟล์แม่แบบสด ๆ ด้วย SheetJS
```

แม่แบบเป็นไฟล์ `.xlsx` commit ไว้ใน repo ไม่ได้ เพราะวันที่เพิ่มคอลัมน์แล้วลืมอัปไฟล์
โรงเรียนจะยังกรอกตามแม่แบบเก่าและ import พังโดยไม่มีใครรู้ว่าพังเพราะอะไร
สร้างสดจาก spec แล้ว **แม่แบบกับตัวตรวจแยกกันไม่ได้โดยโครงสร้าง**

pattern นี้ล้อ `getMediaCardOptions` ที่ส่ง allowlist ไปสร้างฟอร์มอยู่แล้ว

## ลำดับบังคับ

```
ชื่อโรงเรียน + โลโก้
เทอม/ปี active + วันเปิด-ปิดเทอม (TermData)
        │
        ▼
   นำเข้าครู ────────┐
        │            │
        ▼            ▼
 นำเข้านักเรียน   นำเข้าตารางสอน   (ตรวจ teacher_id กับ users)
        │            │
        └─────┬──────┘
              ▼
      ตั้งครูที่ปรึกษา (HR)
```

ตารางสอนต้องมาหลังครู เพราะตัวนำเข้าเช็ค `users.username` ก่อน — ของเดิม `continue`
ทิ้งแถวเงียบ ๆ ไม่บอกใคร ต่อไปนี้เป็น **ข้อผิดพลาด** บล็อกทั้งไฟล์

HR ต้องมาหลังนักเรียน เพราะรายชื่อห้องดึงจาก `users.department` (ข้อ 14)

## เทส

`test/import.test.js` ใหม่ — ยิงผ่าน HTTP layer เหมือนไฟล์อื่น

- base64 หรือ string เข้ามา → **throw** ไม่ใช่ success (บั๊กที่ซ่อมรอบ 1 ต้องกลับมาไม่ได้)
- ตารางสอนอ้างครูที่ไม่มี → ข้อผิดพลาด บล็อกทั้งไฟล์ ไม่เขียนอะไรลง DB เลย
- อัปตารางสอนซ้ำไฟล์เดิม → จำนวนแถวเท่าเดิม ไม่มีแถวซ้ำ
- อัปนักเรียนไฟล์ที่ขาดคนไป → คนที่หายยังอยู่ในระบบ
- รหัส `'01903'` ผ่านทั้งเส้นทางแล้วยังเป็น `'01903'` ไม่ใช่ `1903`
- `DELETE` ตารางสอนกวาดเฉพาะเทอม active ไม่แตะเทอมอื่น
- `getImportSpec` อยู่ใน `READONLY_ALLOWED` (โรงเรียนหมดสัญญายังดาวน์โหลดแม่แบบได้)
- `test/import_client.test.js` ดึง parser ฝั่งหน้าเว็บออกมารันใน node แล้วเทียบผลกับ
  `prepareRows()` ฝั่ง server — สองฝั่งตัดสินต่างกันเมื่อไหร่ เทสแดงทันที
- ตารางสอนที่ชื่อวันเป็น `จ.` / `Monday` → ข้อผิดพลาด ไม่ใช่เขียนเข้า DB แล้วหายทีหลัง

## ไม่ทำ

- **ไม่ทำ wizard บังคับทีละขั้น** — กันตั้งค่าไม่ครบได้ดีกว่า แต่โรงเรียนที่อยากดูก่อน
  ตัดสินใจจะอึดอัด และเพิ่ม state ที่ต้องดูแล
- **ไม่ทำไฟล์นำเข้า "ห้องเรียน" แยก** — ดึงห้องจากนักเรียนได้อยู่แล้ว และการพิมพ์ชื่อห้อง
  ซ้ำในไฟล์ที่สองคือทางให้มันไม่ตรงกัน
- **ไม่แตะรหัสผ่าน plaintext ในรอบนี้** — `checkLogin` เทียบตรง ๆ ทั้งระบบ
  เป็นงานแยกที่ใหญ่กว่านี้ แต่ต้องเขียนไว้ในคู่มือว่าไฟล์นำเข้ามีข้อมูลนักเรียนจริงอยู่ข้างใน
- **ไม่ทำค่าตั้งรายโรงเรียนสำหรับ `WEEKS_PER_TERM` (20) โควตาขาด 20% และ prefix กลุ่มสาระ**
  — เป็นมาตรฐาน สพฐ. เหมือนกันทั้งประเทศ
- **ไม่นำเข้าคะแนนหรือประวัติเช็คชื่อย้อนหลัง** — โรงเรียนเริ่มใช้กลางเทอมให้เริ่มนับใหม่
