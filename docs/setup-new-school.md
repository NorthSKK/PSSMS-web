# ส่งมอบระบบให้โรงเรียนใหม่ — ฝั่งเรา

คู่มือนี้เป็นของ **คนดูแลระบบ (เรา)** ไม่ใช่ของโรงเรียน
ฝั่งที่ธุรการโรงเรียนทำเองอยู่ที่ [`school-onboarding.md`](./school-onboarding.md)
— ส่งไฟล์นั้นให้โรงเรียน **ไฟล์นี้ห้ามส่ง** เพราะพูดถึงคีย์และคำสั่งที่แตะข้อมูลได้

> ⚠️ **ห้ามใส่ค่าจริงลงไฟล์นี้** — ไม่มี `DATABASE_URL`, คีย์ R2, `JWT_SECRET` หรือรหัสผ่านใด ๆ
> ค่าจริงอยู่ที่ Railway variables กับ `.env.prod` (gitignored, chmod 600) เท่านั้น

**1 โรงเรียน = 1 deployment + 1 ฐานข้อมูล + 1 bucket** ไม่ใช่ multi-tenant
ทุกขั้นข้างล่างนี้จึงทำใหม่ทั้งชุดต่อโรงเรียนหนึ่งแห่ง

## 1. ฐานข้อมูล

สร้าง PostgreSQL instance ใหม่บน Railway (**major version ต้องตรงกับที่ dev ใช้อยู่**
เช็คด้วย `SELECT version()` ที่ฐานข้อมูลเดิม)

ไม่ต้องรัน schema เอง — `db/migrate.js` ทำงานตอน boot: ฐานข้อมูลเปล่าจะถูกสร้างจาก
`db/schema.sql` แล้วบันทึกไฟล์ใน `db/migrations/` ทั้งกองเป็น baseline

⚠️ **migration พังคือเซิร์ฟเวอร์ไม่ขึ้น** โดยตั้งใจ — แอปที่ขึ้นพร้อมตารางผิดรูป
แย่กว่าแอปที่ไม่ขึ้น ถ้า deploy แล้วไม่ตอบ ดู log ตรงส่วน migrate ก่อนอย่างอื่น

## 2. ที่เก็บไฟล์ (R2)

**1 bucket + 1 token ต่อ 1 โรงเรียน** — token ที่หลุดจากโรงเรียนหนึ่ง
ต้องไม่เห็นไฟล์ของอีกโรงเรียน

1. Cloudflare → **R2** → **Create bucket** ชื่อ `pssms-<ชื่อย่อโรงเรียน>`
   Location **APAC** · **ห้ามเปิด Public access** (ไฟล์เข้าถึงผ่าน presigned URL เท่านั้น)
2. **R2 → Manage API Tokens → Create API Token** → สิทธิ์ Object Read & Write
   → **Specify bucket** เลือกเฉพาะ bucket ของโรงเรียนนั้น
   ⚠️ **อย่าเลือก "All buckets"** — นั่นคือการยกกุญแจของทุกโรงเรียนให้ token ใบเดียว
3. ใส่ค่าเป็น Railway variables: `STORAGE_DRIVER=s3` + `S3_ENDPOINT` `S3_BUCKET`
   `S3_ACCESS_KEY_ID` `S3_SECRET_ACCESS_KEY` `S3_REGION=auto`
   (รูปแบบค่าดู `.env.example` และหัวไฟล์ `lib/storage/s3.js`)

**ตั้งไม่ครบ = ปิดฟีเจอร์อัปโหลดเฉย ๆ ไม่ใช่พัง** — การ์ดสื่อการสอนแบบลิงก์
และไฟล์แนบสารบรรณจะปิดตัวเอง Admin เห็นแถบบอกสถานะ ระบบส่วนอื่นใช้ได้ครบ
เปิดโรงเรียนก่อนแล้วค่อยมาตั้ง R2 ทีหลังได้

⚠️ **Node ต้อง ≥ 20** (`engines` ใน `package.json` ล็อกไว้แล้ว) — `aws4fetch`
เซ็นด้วย WebCrypto ผ่าน `globalThis.crypto` ซึ่ง Node เปิดเป็น global ตั้งแต่ 19
production เคยรัน 18 แล้วอัปโหลดพังด้วย `crypto is not defined` ทั้งที่ dev ผ่านหมด

## 3. Service และ branch

Railway service ใหม่ ชี้ repo นี้ · **branch `production`** ไม่ใช่ `main`

| ชั้น | branch | ข้อมูล |
|---|---|---|
| เดโมสาธารณะ `demo.pssms.app` | `main` | สมมติ ล้างทุกคืนตี 3 |
| โรงเรียนจริง | `production` | ครูและนักเรียนจริง |

⚠️ **เปลี่ยน branch ของ service ที่รันอยู่แล้ว ต้องให้ปลายทางชี้ commit เดียวกับที่รันอยู่ก่อน**
ไม่งั้น Railway deploy ทับทันทีที่สลับ

variables ที่ต้องมีอย่างน้อย: `DATABASE_URL` · `JWT_SECRET` (สุ่มยาว **ไม่ซ้ำกับโรงเรียนอื่น**)
· `PORT`

## 4. โดเมน

Railway → service → Settings → Networking → Custom Domain → `<ชื่อย่อ>.pssms.app`
แล้วเพิ่ม CNAME ตามที่ Railway บอก ใน Cloudflare DNS

โดเมนหลัก `pssms.app` เป็นของ **ผลิตภัณฑ์** (repo แยก `pssms-site`) ไม่ใช่ของโรงเรียนใด

## 5. วันหมดอายุการใช้งาน

```bash
node scripts/set-license.js 2026-10-31    # ทดลองใช้ = วันส่งมอบ + 30
node scripts/set-license.js --show
node scripts/set-license.js --clear       # ไม่จำกัด (โรงเรียนเราเอง / เดโม)
```

รันโดยชี้ `DATABASE_URL` ไปที่ฐานข้อมูลของโรงเรียนนั้น
**ไม่ตั้ง = ไม่จำกัด** — ตั้งใจให้ต้องตั้งเอง ไม่ใช่มีค่าเริ่มต้นที่เผลอปล่อยผ่าน

| สถานะ | เงื่อนไข | ผล |
|---|---|---|
| `warn` | เหลือ ≤ 30 วัน | แถบเตือน เห็นเฉพาะ Admin |
| `grace` | เลยกำหนด ≤ 14 วัน | แถบเตือนเห็นทุกคน ยังบันทึกได้ |
| `locked` | เลยกำหนด > 14 วัน | โหมดอ่านอย่างเดียว |

⚠️ **พิมพ์ ปพ.5 และ export ใช้ได้เสมอทุกสถานะ** — เป็นเอกสารราชการที่ครูมีหน้าที่ต้องออก
ผูกกับข้อพิพาทค่าบริการไม่ได้ มีเทสล็อกไว้ที่ `test/license.test.js`

เป็น honest-broker ไม่ใช่ DRM — โรงเรียนที่เข้าฐานข้อมูลได้ย่อมแก้วันเองได้
จุดประสงค์คือให้วันหมดอายุ **มองเห็นและตั้งใจ**

## 6. บัญชี admin ใบแรก

ฐานข้อมูลใหม่มี `admin` / `1234` มาให้ **เปลี่ยนรหัสก่อนส่งมอบ**
แล้วส่งรหัสใหม่ให้โรงเรียนทางช่องทางที่ไม่ใช่ที่เดียวกับลิงก์เว็บ

ถ้าลืมเปลี่ยน การ์ด checklist บนแดชบอร์ดจะขึ้นข้อ "เปลี่ยนรหัสผ่านผู้ดูแลระบบ"
ค้างไว้จนกว่าจะเปลี่ยน — เป็นตาข่ายรองรับ ไม่ใช่ขั้นตอนที่ตั้งใจให้ข้าม

## 7. หัวกระดาษ ปพ.5

**โรงเรียนกรอกเองได้ทั้งหมด** — หน้า **บันทึกคะแนน (ปพ.5)** → การ์ด
*ส่วนจัดการของผู้ดูแลระบบ* → ชื่อโรงเรียน · **ที่ตั้งโรงเรียน** · ผู้อำนวยการ ·
หัวหน้างานวัดผล · หัวหน้ากลุ่มสาระ แล้วกด **บันทึกการตั้งค่า**

เพิ่มเข้ารายการตรวจก่อนส่งมอบ เพราะ **ไม่กรอกแล้วเอกสารพิมพ์ออกมาโดยบรรทัดนั้นว่าง**
ไม่มี error ไม่มีอะไรฟ้อง เจอตอนครูดูกระดาษเท่านั้น

⚠️ `savePrintConfigData` เขียน `sys_data` **ทับทั้งก้อน ไม่ได้ merge** — ฟิลด์ใดที่ฟอร์ม
ไม่ส่งมาจะหายทันทีที่กดบันทึก เพิ่มฟิลด์ใหม่ในอนาคตต้องเติมทั้งใน markup, ตัวโหลด
และ `sysObj` ตอน save · `test/print_config.test.js` ล็อกไว้แล้ว

## ย้อนกลับเมื่อ deploy แล้วมีปัญหา

```bash
git checkout production
git revert <commit>
git push origin production
```

⚠️ `.env.prod` มีแค่ `DATABASE_URL` ที่ตรงกับ production — **`JWT_SECRET` ไม่ตรง**
กับที่ตั้งบน Railway จึง mint token ยิง API production ไม่ได้ ใช้ทำได้แค่ query ฐานข้อมูล

## ข้อห้ามที่ต้องจำ

- **ห้ามก๊อปข้อมูลนักเรียนจริงลงเครื่อง dev** — seed เป็นของปลอมทั้งหมด
- **ห้ามใช้ข้อมูล production ทำเดโม** และ **ห้ามถ่ายภาพหน้าจอจาก production** ทุกกรณี
  ภาพบนเว็บขายถ่ายจาก `db/seed-demo.js` เท่านั้น
- **ห้าม push** `.env`, `.env.prod`, ไฟล์คีย์ใด ๆ
- `DEMO_RESET_ON_BOOT` ถ้าเคยตั้ง **ต้องถอดออกทุกครั้ง** — ปล่อยไว้คือทุก deploy
  ล้างข้อมูลของคนที่กำลังทดลองใช้อยู่
